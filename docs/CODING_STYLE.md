# Go 编码规范

- gofmt 是唯一基础排版来源。包名短、小写、无下划线；文件小写，必要时用下划线，测试以 _test.go 结尾。
- 导出用 PascalCase，非导出用 camelCase，URL/HTTP/ID 缩写统一。常量按可见性命名，不机械全大写；不使用 m_/s_/I 前缀、类型别名风格规定或 dot import。
- 导入按标准库、第三方、项目内部三组，组间空行。短变量用 :=，跨函数/API/配置数据使用明确类型，JSON tag 为固定 snake_case。
- context.Context 是可取消函数第一参数，不传 nil，不放入请求数据模型。生命周期对象明确持有与释放责任。
- 每个 goroutine 有退出和等待机制；串行转换不机械启动 goroutine。及时 defer 清理，关注部分初始化失败、循环 defer 和取消后的独立清理预算。
- 错误显式返回，用 %w 保留原因、errors.Is/As 判断。网页失败不 panic，不比较错误字符串；清理错误记录且不覆盖原业务错误。
- 接口只用于真实替换边界，由使用方定义；不为所有 struct 建接口，不建空 util/common/pkg 或仓储层。
- 导出 API 与复杂并发边界写用途、约束、错误的 Go doc；不写作者/日期或逐行语法解释。
- 日志结构化，使用请求 ID、事件、阶段和必要原因；不输出正文、Cookie、授权头或 URL 查询串。
- 新参数、配置、过滤或部署行为必须同步实际文档和测试。测试验证行为与边界，不镜像实现步骤。
